Section#1 Accuracy and What This Emulator Is Good For
--------------------------------------------------------------------------------------------------------
Accuracy is a double-edged sword so I have tried to avoid making the program more accurate in some ways,
otherwise it can lead to emulating crashes which would happen on the original N64 hardware. If you don't
agree with this type of design, try the Ares N64 emulator instead: https://ares-emu.net/

And if you want to play ROMhacks, this is the right emulator for them. ROMhacks hosted at the URL below:
https://github.com/BruceShankleIV/Project64-1.6.2-ROMhacks-Collection This emulator will also work great
with retail games assuming they have been tested and have optimized emulation settings and plugins used.

See Section#4 Running ROMhacks if you are running ROMhacks not hosted above, and remember to check your
ROM Notes tab after loading a game to see what plugin(s) should be used with the game or hack.
--------------------------------------------------------------------------------------------------------

Section#2 Hardware Compatibility
--------------------------------------------------------------------------------------------------------
This program was originally designed on very old versions of Windows which Version 1.6.2 doesn't support
anymore. PJ64 v1.6.2 was developed using a Windows 10 Desktop PC and isn't expected to function properly
on older versions of Windows like Windows 2000 and Windows 95. Theoretically, this program may work on a
Windows XP machine, but may necessitate removing plugins which do not work on XP from the plugin folder.
This would mean removing: GLideN64 and Icepir8's plugins.

However, even if you have an older or lower-end computer, the app should function with it for some games
assuming you are using the default Jabo plugins. Some good games to try are Mario 64, Ocarina of Time, &
Majora's Mask. Suggested ROMhacks are Star Road (Super Mario 64) and The Missing Link (Ocarina of Time).
If some graphics don't display with the default Jabo video plugin, then try Glide64 Final to substitute.

Section#3 Plugin Details
--------------------------------------------------------------------------------------------------------
DISCLAIMER: DON'T add any plugin to the plugin folder. You DON'T NEED TO! ADDING DLLS CAN CAUSE A CRASH!


Video (graphics) plugin:

Direct64 v0.5.03.25 - One of the oldest video plugins included in this project. It was only included for
		      machines with GPU's that do not support OpenGL and in the case that the user needs
		      to play a game with graphics emulation requirements not supported by Jabo's Direct
		      video (Pumkin Tower/Ultimate Trial). However, the video plugin is missing numerous
		      graphics effects, especially fog being a very noticeable one. There's also texture
		      issues, issues with pause/unpause on MQ Debug roms, and many other issues with it.
		      Try the video plugin if none of the included Jabo video plugins work with the game
		      if it happens to be that other plugins don't work at all with any game on your PC.
		      My 5th (least) favorite video plugin because it's not very useful.

Glide64 'Final' Date: Dec 29 2011 - If you need a video plugin for modern hacks that supports alpha
				    blending and a (low res) framebuffer, and your PC doesn't support
				    GLideN64, this is your best bet. Easily my 3rd favorite video plugin
				    and a very good pick all-around if it works on your PC.

GLideN64 rev.xxxxxxx - This would be my favorite video plugin if it used Direct3D8 instead of OpenGL for
		       better PC support and didn't experience tearing during fullscreen or input delay.
		       If you use a modern PC or you want to play modern hacks though, you'll want this.
		       My 2nd favorite video plugin.
		       Note: This plugin supports GIM by turning off “Emulate framebuffer” like Glide64.

Project64 Legacy Icepir8's LLE - This plugin is faithful to the graphics of an original N64, in terms of
				 its blurry low resolution low level style. However, it does not support
				 F3DEX3 like GLideN64 does and also has a compatibility issue with Pmem.
				 My 4th favorite video plugin, I'll use this if I want to feel like I am
				 living in the 1990s/early 2000s.

Jabo's Direct3D8 1.6.2 - This is my personal favorite video plugin for these reasons:
			* No screen tearing in fullscreen
			* No input delay
			* Works with all older ROMhacks
			* Works on all Windows PC's
			* Basic framebuffer support for Zelda, Mario Kart, and Banjo.
			(Or at least, mostly. The Majora's Mask grandma's stories images don't display!)
			(And an issue with Lens of Truth framebuffer emulation with Shiro / Stone Mask.)
			* Supports native widescreen with adjusted aspect (effectiveness varies by game)
			 Unfortunately, this video plugin doesn't perform well with newer ROMhacks which
			 were made with tools that import textures which won't get proper alpha blending
			 in this plugin or uses a microcode not supported by this plugin like F3DEX3. In
			 these cases you should use another video plugin. Otherwise, just use this if it
			 is effective for the game you're trying to run. To setup the widescreen, enable
			 the, “Adjust game aspect ratio to match yours”, from the plugin's advanced tab.
			 Note that there may be some cases where graphics don't show up when using this,
			 in that case it's GPU related and you should try a different video plugin.


Audio (sound) plugin:

Jabo's DirectSound 1.6.2 - The most PC compatible sound plugin. If a game won't boot using this plugin,
			   but the same game is able to boot whilst using No Audio or Shankle Azi, there
			   are two settings in the ROM Settings tab, which either of them can be toggled
			   to fix a ROM boot issue: “Sync Game to Audio” and “Jabo AI”. Turning the Sync
			   setting off should be tried first, if the results aren't good then you should
			   turn Jabo AI on and see if the ROM sounds or performs better (no stuttering).
			   Either option will also be used to fix a game running at the wrong speed with
			   this sound plugin, as by default, the emulator syncs game speed to the audio.
			Note: This is a Hex edit of Jabo's 1.6.1 from jabosoft.com/blog/project64-update
		Note: The emulator can slowdown dramatically if your sound device is unplugged with this
		due to Sync Game to Audio. If this happens, all you have to do is plug back in and wait.

No Audio Plugin - Use this plugin when you want to hear nothing. It is better than having the volume all
		  the way down in Azi because in Azi it is not always mute making this your best choice.

Shankle's LINK's AziAudio [SEP2023] (1.0) - Great general-use option and sound plugin used for GLideN64.
					    However, this plugin can have issues with some computers, so
					    then you would use Jabo's DirectSound with those edge cases.


Input (controller) plugin:

Jabo's DirectInput7 1.6.2 - Unless this is your preferred input plugin for its ease of setup, you should
			    use a different input plugin if your PC supports a different input plugin...
			    It's bad for keyboard because there is no binding to allow precision aiming.
			    And you can't map the controller's buttons to the N64 buttons: it's reverse.
			    Despite all the negatives, this is the default since it works for everybody.

Shankle's N-Rage's DirectInput8 1.6.2 - Enable XInput if your device uses XInput (Xbox 360 Controllers).
					This is a very solid plugin, a few games need it to work at all.
					But Octomino SDL2 could be used when using an XInput controller,
					so long as the game is compatible with the Octomino SDL2 plugin.
					Use F and G keys to modify range for keyboard precision aimings.

Shankle's Octomino SDL2 Input 0.1.1 (1.2) - Plug and play plugin, no configuration needed. It's config'd
					    through configuring controller plugin after a ROM is opened.
					    It has many options, some not even seen in N-Rage, and auto-
					    configures your controller using the gamecontroller database
					    so you will not have to map out all of your button mappings.
					    Some games require you to use N-Rage's input plugin however.


RSP (reality signal processor) plugin:

Project64 Legacy Icepir8's RSP - Only use this RSP when you have to because it's very prone to slowdown.
				 It is only needed for super niche games (indicated by Game.ini) so stay
				 with the default RSP plugin unless a game specifically needs to use it.
				 To know when you need to use this RSP, always view a ROM's Plugin Note!

RSP Emulation Plugin - The most compatible, use this unless Icepir8's RSP is needed for a specific game,
		       or if Icepir8's RSP is needed for a game with Icepir8's LLE (usually, it is not).
		       Note: This is a hex edit of the 1.6 RSP and syncs with the app with the dll name.

Static Interpreter - Currently only needed for GameBoy transfer pak emulation. Added to the project last
		     minute, unknown how this one behaves.

Section#4 Running ROMhacks
--------------------------------------------------------------------------------------------------------
ROMhacks are essentially new games created from existing game ROMs, usually commercial titles like SM64,
Ocarina of Time, or Majora's Mask. They are released in a patch format like .ppf, .bps, or .xdelta. This
emulator loads ROM files only, so you must first apply the patch to the correct N64 ROM. If this ROMhack
patch is not obtained from the Project64 1.6.2 ROMhacks Collection repository outside of an unregistered
folder, then this hack likely needs a Game config entry registered in the Game.ini. If this happens, you
won't get information from the emulator about what plugins are required or suggested for this ROMhack!!!
The hack may also be prone to crashing or other kinds of unexpected behavior if you aren't using certain
ROM Settings with it, depending on what was hacked into the ROM, and the properties of the original ROM.
A good idea to start with is using the same ROM Settings and fixes used for the original ROM. This would
resolve most issues you would have just using the defaults, but there can be some edge cases. Generally,
not enabling the Jumper Pak is a good tip since that would emulate with the N64's base 4MB RAM capacity.


For Zelda ROMHACKS, Majora's Mask hacks should always use the same internal name as their baserom, which
is either ZELDA MAJORA'S MASK or THE MASK OF MUJURA. THE LEGEND OF ZELDA should get used for all Ocarina
of Time ROMhacks that are based off of all release ROMs like Version 1.0, 1.1, and 1.2 and for all hacks
which use monochrome, like during a flashback cutscene, or the sepia filter at the very end of the game.

Then you would setup a Game config entry, which can vary drastically from the original game depending on
how much the hack differs from the original game with a Cheat0 added to fix any emulation/plugin issues.

Section#5 How to Use The ROM Browser/ROM Notes System
--------------------------------------------------------------------------------------------------------
The ROM browser system, controlled by Game.ini, is supposed to work like this:

You select your ROM directory and then all those ROMs will be loaded in the ROM browser. They get marked
with colors based on compatibility. Green would indicate that it works with any of the included plugins.
Yellow would indicate that at least one video, audio, input, or RSP plugin is needed for you to play it.
Red indicates the game is illegit somehow and I suggest not to play them, especially with this emulator.

Green - Compatible

Yellow - Semicompatible

Red - Illegit

PLEASE NOTE - Games marked as Compatible were only tested with a few of the video plugins included (more
video plugins were added to the project over time to account for users with weaker hardware and specific
ROMhacks which needed an older video plugin to be playable depending on the user's GPU and the ROMhack).
Games marked as Compatible are only tested between GLideN64, Jabo's Direct3D8, and Legacy Icepir8's LLE.
These 3 video plugins are the best general-use options available.

The user should refer to the plugin note for Semicompatible games if given to see what plugin(s) to use.
The user should refer to the plugin note for Compatible games if given to see viable plugin suggestions.
The plugin note will be found from the settings window after opening the ROM in the ROM Notes section or
from the ROM Notes window which appears from right clicking the ROM after it gets loaded in the browser.
And the core notes are for developers and testers, not casual users.

Section#6 Emulator Advanced Settings Overview
--------------------------------------------------------------------------------------------------------
After unchecking Hide Advanced Settings under Settings->Options and reloading the Settings window, there
will be a ROM Settings tab. The tab is looking at the currently loaded Game's CRC inside PJ64DB\Game.ini
and showing you what emulation options are enabled for the game, what emulation options are disabled for
the game, and what emulation options are forced ON or forced OFF due to another setting. This section of
the guide shall give you a quick rundown on the default settings tab and all the ROM Settings!

Save Type: Varies by default
The emulator usually correctly figures out the right save type but assumes 4kbit for EEPROM, not 16kbit.
This means all games which require 16kbit EEPROM need to have the save type manually set in the Game.ini
from the ROM Settings, or type it. You may also need to specify FlashRAM or 256kbit SRAM for some games.
You can however autodetect to 16kbit EEPROM from the advanced tab if this suits your usage of Project64.

Counter Factor: By default, 2 but changeable from the advanced tab
* Forces Lag on if not set to 1
Another very game-dependent setting, this essentially just adds lag. This is needed for some games to be
stable, for others it breaks them completely or causes extreme flickering (video plugin dependent). 2 is
a safe default so it's not suggested you go any lower (or higher) from this unless you are playing games
that you are confident require 3 or will work with 1. Setting to 1 will notably get rid of some flickers
and cause faster loading times and you will never have any lag in a game (if Lag is turned off with it).

Sync Game to Audio: By default, on
* Forced off if sound plugin isn't Jabo's DirectSound
* Forced on by Jabo AI
* Forces Limit FPS on while a game is running
This setting is needed for Jabo's DirectSound to not sound awful in popular titles. It works differently
from the Sync game to Audio option in the audio config, which allows the user to enable per-ROM from the
registries and also does not work for some games which this Sync Game to Audio will work for. Some games
don't work with this option and either run too slowly or refuse to boot. For these games, turn Sync Game
to Audio off and listen to the sound, then enable Jabo AI and use whichever worked better.

Jabo AI: By default, off
* Forced off if sound plugin isn't Jabo's DirectSound
* Forces Sync Game to Audio on
Just like Azi AI described below but for Jabo_Dsound, also a good substitute for Sync Game to Audio if a
ROM doesn't work well with Sync Game to Audio on/off by itself, or if this fixes Jabo_Dsound stuttering.

Align DMA: By default, off
This setting fixes broken interface positions in games but also emulates a limitation breaking ROMhacks.
There is currently only one game which needs this setting, but there could be more in the future. If CPU
Recompiler is turned off, you may want to turn this on if that still doesn't fix a game's graphical bug.

Legacy AiLenChanged: By default, off
* Forced off if sound plugin is No audio
This is an alternate AI function from Project64 Legacy 1.6.4 which works better sometimes (not always).

Azi AI: By default, off
* Forced off if sound plugin isn't Shankle AziAudio
This emulates AI for Shankle AziAudio, used to get sound working in some games or to solve Limit FPS off
issues while using the Shankle AziAudio plugin.

Delay RDP: By default, off
It's either needed or it's not. Notably fixes the HUD in Kirby 64 for some reason. The setting is needed
for some games to boot.

Jumper Pak: By default, off
This emulates the Jumper Pak which comes with original Nintendo 64 hardware. If you want to make a game
which works on original hardware, you need to enable this option. Most ROMhacks do not work on original
hardware and many N64 games do not either so you generally want to keep this on. But in the cases where
it can be turned on, it reduces the emulator's total memory use and generates smaller-sized savestates.

Signal: By default, off
It's either needed or it's not. The setting is needed for some games to boot.

Delay RSP: By default, off
It's either needed or it's not. The setting is needed for some games to boot. Known to break sound in
some games when used incorrectly.

Virtual SD Card: By default, off
This setting is specific to ROMhacks which save data to an SD Card for some reason. Said data is managed
via the Options menu and the files on the newly created partition (decompression of the virtual SD card).
Currently only Mario Builder (v1.1 release) uses this setting in the Game.ini so this one is super niche.

59 FPS: By default, off
This setting fixes a game running at the wrong speed (misdetected as 50FPS) but it is very very rare...
There is currently only one game which needs this setting, but there could be more in the future.

Delay SI: By default, off
It's either needed or it's not. Notably fixes GB Tower not working with the Static Interpreter RSP while
using N-Rage. The setting is needed for some games to boot.

Recompile RCP RSP: By default, variable
* Forced on if the video plugin is not Icepir8's LLE or if the ROM is known to require it (internal name)
This should usually be on for performance, most of the time it will be forced on, you should only need to
toggle it per-game when using Icepir8's LLE video plugin due to incompatibility between the two. If this
isn't enabled, the RCP RSP will be interpreted instead (exclusively for select cases with Icepir8's LLE).
-
More technical explanation from n64brew.dev:
The Reality Coprocessor, or RCP, is one of the two main processors on the Nintendo 64 board. Split into
two components, the Reality Signal Processor and Reality Display Processor, it cooperates with the other
main processor, the VR4300 CPU to draw 3D graphics, perform matrix calculations, and produce audio. The
Reality Signal Processor, or RSP, is the portion of the RCP responsible for matrix math, lighting
calculations, clipping, shading, and other highly parallel graphics tasks, as well as audio processing.
-

Recompile VR4300i CPU: By default, on
This should almost always be on unless it's not possible to get a game working with recomp optimizations
in which case disabling this is mandatory. When enabled, you should take advantage of all optimizations.
Those optimizations are: Lag unchecked, Translation Lookaside Buffer unchecked, Register Caching ON, and
Protect Memory / Enlarged Buffer OFF. If experiencing issues with that combination, try until you arrive
at whatever combination works best for the current game.



VR4300i CPU Recompilation Optimizations


* This is one of the more complex settings to understand so I wrote lots of tips to fully understand it!

Lag: By default, off
* Forced off if Recompile VR4300i CPU is off (interpretation goes through a different code path)
* Forced on if emulating with a specified Counter Factor >1 in the ROM Settings tab (ignore default CF).
* E.g, you set Counter Factor 1 by default and you're using the default Counter Factor, the setting goes
out of effect for you to test if a game works ok with it, otherwise it has no effect but can be toggled.
* This is for the sake of convenience testing regarding optimal timing settings. If a game works without
any issues with Counter Factor 1 default, the setting can be left off.
* Essentially, when configuring ROM Settings, you should have Counter Factor 1 by default and review for
any abnormal behavior, then if you see something caused by it off, try turning this setting on, if it is
not working still, then you need to increase Counter Factor in the ROM Settings tab (force-enables Lag).
Lag reduction is helpful to reduce load times and achieve consistent framerates and create a more
satisfying gaming experience, but this remains a game specific setting since some games aren't stable
without lag. To know when you can get by with this requires in-game testing. Disabling lag can reduce
performance and increase boot times, so this setting should be used carefully and with caution!

Translation Lookaside Buffer: By default, on, but can be force disabled from the advanced tab
* Forced off if Recompile VR4300i CPU is off (interpretation goes through a different code path)
* Forced off if force disabled from the advanced tab
This Translation Lookaside Buffer is either required for a game or not. If the game does not require it,
it's best to turn it off to avoid issues that this setting can cause, although with most games it's fine
to leave it on. Generally, just leave this on unless you know a game works better with, or needs it off.
Turning it off notably improves performance and can get ROMhacks working.

Protect Memory / Enlarged Buffer: By default, off but changeable from the advanced tab
This is a self-modifying code emulation setting and the “Larger Compile Buffer” option added in v1.4 put
into one unified setting since they work best together. This should be kept off as much as you possibly
can since enabling it can introduce stutter and performance problems, but sometimes it's needed. You'll
need to test on a game specific basis to see when you do and don't need this enabled. But if you desire
stability, I suggest checking this as ON by default from the advanced tab. This option also causes some
sudden crashes when enabled with Icepir8's LLE selected as the video plugin so I advise against having
this setting ON by default while using Icepir8's LLE as your default video plugin!

Register Caching: By default, on but changeable from the advanced tab
Usually boosts performance without causing some negative side effects. But those side effects do include
causing a game to crash suddenly without warning, and can include distorted graphics/sound/fail to boot.
This is left on by default since some games don't run at the proper speed when it's left off and usually
there is no problems when enabled and it should be enabled by default for configing ROM Settings to test
all relevant optimizations for any issues.



The default area is just the defaults used for the ROM Settings whenever it says “Default”.
Then there is the force settings, they are self-explanatory. Keep in mind that activating these settings
doesn't overwrite Game.ini entries so it is good for testing, but disactivating them overwrites entries.
Just do not go to ROM Settings tab and disactivate these force-enable/disable settings at the same time.

Section#7 Known Issues
--------------------------------------------------------------------------------------------------------
Windowed video capture does not capture sounds, this could get fixed if I find an alternative to ffmpeg.

Mouse cursor isn't hidden in fullscreen with Icepir8's LLE because that video plugin hides the cursor.

Plugin-specific issues - This app relies on a lot of different plugins to work, many of them are closed-
source but have specific bugs in them which means issues specific to many of the plugins in the emulator
will likely never get resolved. All of the following plugins included in the emulator are closed-source:

Direct64 v0.5.03.25
Project64 Legacy Icepir8's LLE
Jabo's Direct3D8 1.6.2

Jabo's DirectSound 1.6.2
No Audio Plugin

Jabo's DirectInput7 1.6.2

Project64 Legacy Icepir8's RSP
RSP Emulation Plugin

Glide64 is open source but I cannot get it to compile.

If you try to record audio with Jabo's DirectSound before booting a game, it won't work.

IMPORTANT: Plugin hardware-specific issues - Some issues you see with a plugin may be specific to YOUR
device only! There's several examples, common one's being shadows in Super Mario 64 or the fire effect
around the Ocarina of Time logo. If see'ing such things, all you can do is change to a different video
plugin and pray or get a better GPU. My GTX 1660 Super has no issues with any of the graphics plugins.

Cheat code issues - The cheat codes in this emulator have not been extensively tested, it's likely there
are some bad codes which may cause crashes or don't behave correctly due to lack of testing and whatnot.
But the one's for Mario 64, Ocarina of Time, and Majora's Mask have been tested extensively and updated.

Input delay with any accurate video plugin with a dedicated framebuffer. To resolve this for GLideN64 w/
SM64 Hacks, ensure the internal name of the ROMhack is, “SUPER MARIO 64” if it does not use framebuffer.
Note: You can update internal names of ROMhacks with a simple hex editor like HxD in the header section.

GLideN64 fullscreen tearing. No good fix for this, the Vsync option won't even help. Turning framebuffer
off fixes this but having it off by default will break graphics in hundreds of games.
